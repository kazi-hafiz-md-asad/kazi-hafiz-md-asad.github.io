Efficient NLP & LLM adaptation

Reducing model cost without disguising the quality trade-off

I study knowledge distillation, low-rank adaptation, quantization, gradient checkpointing, adaptive rank control, and compression-aware training for NLP systems under constrained memory and compute.

Current questions

  • How much capacity is necessary for a target task?
  • Which PEFT components produce real gains under matched budgets?
  • How should quality, VRAM, runtime, convergence, and stability be reported together?

Current work

02

Trustworthy evaluation

Turning experimental discipline into a research contribution

Efficiency is only meaningful when claims are tied to controlled comparisons. I build evaluation pipelines around matched compute, leakage prevention, ablations, repeated runs, statistical testing, and traceable experiment configuration.

Evaluation principles

  • Match data, model access, optimization, and resource budgets.
  • Separate validation decisions from held-out evaluation.
  • Report negative and redundant components, not only wins.
  • Preserve environments, seeds, configs, logs, and artifacts.

Evidence I track

Predictive quality, peak GPU memory, wall-clock runtime, convergence stability, calibration, sensitivity to schedules, significance tests, and null-model behavior.

03

Graph & hypergraph learning

Finding when higher-order structure is genuinely useful

I compare pairwise graph projections with incidence-based hypergraph representations to determine when multi-entity interaction structure improves protein-complex recovery.

Benchmark design

  • Nine IntAct MITAB interaction datasets.
  • Held-out, leakage-controlled evaluation.
  • Matched-k clustering comparisons.
  • Null models, significance testing, and GO enrichment.

Research objective

Move beyond the broad claim that “hypergraphs are better” and characterize the empirical conditions under which higher-order incidence structure adds measurable value.

How I work

A research workflow built for credible comparison

01

Specify the claim

Define the exact quality, efficiency, robustness, or representation question before optimizing the system.

02

Control the comparison

Match budgets, data access, preprocessing, evaluation splits, and tuning opportunities.

03

Stress-test the result

Use ablations, repeated runs, null models, sensitivity analysis, and statistical validation.

04

Make it reproducible

Pin environments, log configurations, isolate hardware, preserve artifacts, and document failure modes.
